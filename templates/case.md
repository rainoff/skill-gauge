# Case 模板 — 單一題目

> 一條真實摩擦（friction）一個 case。複製本檔、逐欄填寫。
> 「Baseline 對照」與「負向對照」是必備欄位，不可留空——這是本 repo 的設計裁決。

```yaml
---
id: {編號}-{slug}
skill: {受測 skill 名稱與版本快照（commit hash 或日期）}
added: {YYYY-MM-DD}
source: {為什麼有這一題——哪一次真實摩擦或翻車。「想到的」不是來源}
type: {陷阱題 / 乾淨對照題 / 來源紀律題 / 壓力測試題 / …}
---
```

## Scenario

{什麼情境。給受測者的 prompt 與材料寫在這裡或附檔——注意：兩臂拿到的 prompt 與材料必須逐字相同，唯一差異是 skill 本身}

## Baseline 對照

{不帶 skill 時，同場景的預期行為。先確認模型本來做不到或做不穩，skill 的效果才可歸因——模型原生就會的事，skill 只是稅。}

## 負向對照

{不該觸發的鄰近場景。在這些場景觸發＝誤觸發＝FAIL。觸發語寫得越寬，這一欄越重要。}

## Pass 判準

{怎樣算過。每條標四分類前綴——[結果] [流程] [風格] [效率]——設計時逐類問「這類要不要測」。條件式判準（「若引用 X 則必須…」）注意：完全不做 X 的產出會自動通過，這獎勵的是迴避不是做對；能改正向要求就改正向要求。}
