# Pre-registration 模板 — 開跑前先寫定

> 本檔在**開跑之前**寫完並 commit。跑完不得回頭改判準；要改，開新版本、留下這一版。
> 防的是最常見的自欺：先看結果，再挑會讓結果好看的判準。

## 座標宣告（必填——結論只在這四個座標內成立）

| 座標 | 本次量測的值 |
|------|-------------|
| 模型 | {受測執行用哪個模型？評分用哪個模型？兩者都要填實際跑的值，不填「預計」} |
| harness | {量測環境裡還有什麼：全域規則？記憶？其他 skill？隔離做法寫具體（見下方執行紀律）} |
| 任務分佈 | {題目覆蓋哪些任務型態？沒覆蓋的型態，結論原理上不外推} |
| 使用者既有能力 | {prompt 裡自帶了多少紀律？使用者（或題目）既有的習慣等同一層看不見的 harness——對照臂拿到的紀律句要逐字列出} |

## 受測物

- skill：{名稱＋版本快照（commit hash 或日期）——模型與 skill 都會更新，凍結不了就記錄}
- 兩臂定義：
  - with_skill 臂拿到：{逐項列——skill 全文？skill 連帶載入的其他東西？}
  - 對照臂拿到：{逐項列。**誠實檢查：對照臂是不是真的「無 skill」？** 若 prompt 含 skill 的核心紀律句、或材料本身是 skill 某一步的產物，你量到的是殘餘差值不是完整效果——現在就寫下來，不要等跑完才發現}

## 四族斷言

| 族 | 進不進評分 | 本次內容 |
|----|-----------|---------|
| 前置檢查（gate） | ❌ 不進分。任一不過＝該 run 無效，記 invalid、補跑 | {格式、語言、自包含等「模板照抄就會過」的項目全部歸此——它們進評分＝拿考卷作答} |
| 事實紀律 | ✅ 逐項二元，附證據位置 | {不捏造識別碼／日期／出處、不把推測寫成事實…} |
| 判斷紀律 | ✅ 逐項二元 | {不代替裁決者下結論、不擅自標記推薦…} |
| 取向觀察 | ❌ 不進分，強制記錄 | {二元判準抓不到的風格與取向差異；原始輸出一律留存} |

## 規模

{題數} × 2 配置 × {每配置 run 數} ＝ {總 run 數}。
小規模下，加重複次數通常比加題目划算；設了幾就跑滿幾——設 3 跑 1 的數據不要用。

## 能說／不能說（先寫死）

- **能說**：{描述性、僅限本次 run 的話}
- **不能說**：{因果通則／外推到題組外任務／跨模型比較／…——現在寫，跑完照著念}

## 執行紀律

1. fresh session、乾淨 workspace，每 run 隔離。
2. 隔離操作化（採 skill-forge cli-executor 做法）：暫存沙箱目錄＋`--setting-sources project --strict-mcp-config`，受測 skill 以 project 層放入沙箱——全域規則與記憶不載入，兩臂旗標對稱。用前先做已知答案檢查：確認正常環境讀得到的全域內容，在沙箱內真的讀不到。
3. 對照臂的誠實檢查：確認對照臂不只「沒用 skill」，而是「skill 不在可用清單上」——skill 在清單上但沒被用，量到的是上界不是乾淨差值。
4. gate 不過的 run 記 invalid 補跑（逐字相同 prompt），不算失敗也不算通過。
5. 評分模型欄位**實填**，不留佔位符。
6. 跑完先填 results（數據），才可寫任何結論；結論措辭受「能說／不能說」約束。
