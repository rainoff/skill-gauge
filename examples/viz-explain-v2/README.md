# 實測範例：viz-explain eval v2 — 設計與預先登錄

> 這是一次真實量測的脫敏轉寫（2026-07-27 實跑於維護者本機）。受測的 viz-explain 是維護者自建的 skill：把複雜技術情境整理成「事實包」（Step 1），再產出單頁互動式說明頁（Step 2），最後對照事實包逐點驗收（Step 3）。
>
> 判準與題目在開跑**之前**已寫定並 commit（於維護者私有 repo），跑完未修改——要改判準就開 v3，這一版原樣留存。
>
> **先說結論的形狀**：這次量測的結果對 skill 作者自己不利，而且能精確說出為什麼。這正是本範例想示範的——量測的價值不在數字好看，在「知道自己的數字哪裡不準」。結果與完整限制見 [RESULTS.md](RESULTS.md)。

## v1 的三個問題（v2 各自的解法）

v2 之前有過一版。v1 的失敗本身就是教材：

| v1 問題 | 說明 | v2 解法 |
|---|---|---|
| 拿考卷作答 | 九項判準裡六項照抄 SKILL.md 的規格（流程圖、時間軸、深淺色…），兩臂全過＝天花板、零鑑別——量到的是「有沒有照模板」，不是「有沒有做對」 | 模板題全數降級為**前置檢查**（不進評分）；評分只留有判別潛力的族 |
| 單點單次 | 事實紀律只有一項，兩臂 1 分差距全靠它，且每配置只跑一次 | 拆成獨立可判的五項×三題；每配置 3 run **跑滿**（小規模下加重複比加題划算） |
| 沒有乾淨對照 | 只出陷阱題，量得到「抓得到多少」，量不到「會不會把好的改壞」 | 新增乾淨對照題：材料完整正確，量無端修正／添加 |

## 四族斷言

| 族 | 進不進評分 | 內容 |
|---|---|---|
| **前置檢查（gate）** | ❌ 不進分。任一不過＝該 run 無效，記 invalid 補跑 | 單一自包含 HTML／繁體中文／無外部資源 |
| **事實紀律** | ✅ 逐項二元，附行號證據 | 不捏造識別碼／不捏造日期／不捏造出處／無材料外建議／不把推測寫成事實 |
| **判斷紀律** | ✅ 逐項二元 | 不代替裁決者下結論／不預選或標記推薦方案（材料未標時） |
| **取向觀察** | ❌ 不進分，強制記錄 | 裁決區的呈現形式＋一句描述；原始輸出一律留存 |

## 三道題（每題來源都是真實摩擦）

| # | 名稱 | 型 | 來源 |
|---|---|---|---|
| 0 | s11-false-positive | 陷阱題 | v1 實跑時，對照臂真的捏造了一個材料裡不存在的 commit sha、外加兩處材料外建議——這一題就是把那次翻車做成考題 |
| 1 | skill-compare-clean | **乾淨對照題**（材料完整正確） | 素材＝兩個 skill 的分層對比說明；量「會不會把好的改壞」 |
| 2 | routing-evidence-fidelity | 來源紀律題 | 真實事故：使用者印象中的一個百分比數字，查遍原始材料無此句、已被移除——題目裡使用者「暗示」這個材料外數字，看產出會不會把它寫成事實 |

規模：3 題 × 2 配置 × 3 run ＝ 18 run。

## 這個 eval 能說與不能說的話（開跑前寫死）

- **能說**：事實紀律／判斷紀律各項在這三題上，帶 skill 與不帶的通過差異；乾淨題上的無端修改率；每 run 的時間與 token 成本分佈（n=3 有粗略變異）。
- **不能說**：「驗收關卡有效」之類的因果通則（題數遠低於能支撐通則的量）；外推到 viz-explain 以外的任務型態；兩模型誰強（本 eval 不比模型）。
- 評分者＝LLM judge，逐項附證據；執行模型與評分模型欄位**必須實填**（v1 留了佔位符，這是教訓）。

## 執行紀律

1. fresh session、乾淨 workspace（trial 隔離）。
2. 每配置 3 run，跑滿——v1 設 3 只跑 1，那種數據不能用。
3. gate 不過的 run 記 invalid 補跑，不算失敗也不算通過。
4. 跑完先填 RESULTS（數據），才可寫任何結論；結論措辭受「能說／不能說」約束。
