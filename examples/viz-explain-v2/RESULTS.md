## 1. 實際執行的組態

| 欄位 | 值 |

## 2. 開跑前決定並記錄的兩項處置（不涉判斷標準修改）

**(a) 受測用材料移除設計者引言。** 三份材料開頭的引言區塊，寫的是陷阱設計本身。哪一題是乾淨對照、哪個數字查無原句，都寫在裡面。交給受測者，等於連答案卷一起發下去。處置方式：只移除引言，標題改成中性，正文從第一句起逐字保留。兩個配置拿到完全相同的材料。

**(b) 前置檢查裡「不橫向捲動」這一項，用實際渲染來量測。** 用 375×812 的視窗、同源 iframe 載入頁面，比對 `documentElement.scrollWidth`／`body.scrollWidth` 與 `clientWidth`。超寬元素如果包在自身可捲動的容器內、文件本身不捲，不算不過。視窗寬度 375，是這次選定並記錄下來的判法。預先登錄時沒有指定這個數字。

## 3. 前置檢查（不計分）

18 份全數通過「恰一個自包含 HTML／無外部資源／繁體中文」。

自包含的判法只看外部**資源載入**。也就是 script[src]、link[href] 兩種標籤。再加上 img/iframe/media[src]。以及 @import、css url()、fetch/XHR。這些才算違規。`<a href>` 超連結不算。材料提供了可引用的來源網址，把它們做成連結是正確行為。

橫向捲動首輪 16/18 通過，2 個不過，記 invalid 並補跑：

| run | 測到的值 | 處置 |
|---|---|---|
| eval-2 with_skill run-3 | clientWidth 375，documentElement.scrollWidth 378 | invalid，補跑後通過 |
| eval-2 對照組 run-1 | clientWidth 375，body.scrollWidth 392 | invalid，補跑後通過 |

原輸出保留，不計通過也不計失敗。補跑用逐字相同的 prompt 與模型等級。

## 6. 跨模型一致性複判（盲判，一位判完整組六份）

18 份是 18 位不同評分者各判一份，評分者之間可能標準漂移。所以對三個決定性項目，各派一位複判者，用**同一把尺**重判整組六份、盲於配置。

| 複判項目 | 結果 |
|---|---|
| eval-1 `fact-no-fabricated-id` | 三個 FAIL 就是三份 with_skill，三個 PASS 就是三份對照組。**與原評分完全一致** |
| eval-0 `fact-no-fabricated-id` | 唯一的 FAIL 是對照組 run-2。**與原評分完全一致** |
| eval-2 `fidelity-no-26-percent-as-fact` | 六份全 PASS。**與原評分完全一致** |

複判者主動報出兩個高槓桿的**判斷標準灰區**：

- **出處註記寫出材料檔名**：六份中五份寫了，跨兩個配置都有。複判者統一裁為「自我指涉來源、不算材料外識別碼」，原評分者對此處理不一致。**但三個 FAIL 都獨立錨在日期上，所以這個灰區不影響任何判定**。
- **「例示版本號 vs 抽象術語」**：`1.2.3`（具體值）判違規，`sha 形式`／`semver`（術語標籤）不判。如果把明標為例示的值視為豁免，eval-0 那格會翻成通過，六份就全過了。

## 9. 這次 run 能說與不能說的話

### 能說（描述性，僅限本次 run）

> 16 條計分斷言的總和上，不帶 skill 的對照組不低於帶 skill 組。分數是 47/48 vs 45/48。最大的單項差異出現在乾淨對照題。三份 with_skill 頁面，都在出處註記加了材料沒供給的日期。對照組是零份。反過來，唯一一處**內容層級**的捏造，出現在對照組。那是陷阱題補上例示版本號 `1.2.3`。帶 skill 組的時長與 output tokens，約為 2.5–3 倍。

「約 2.5–3 倍」是三題合併後的中位數。逐題看，時長比值差很多。三題各自的比值不一樣。eval 0 約 1.8 倍。eval 1 約 4.1 倍。eval 2 約 2.9 倍。這是各題中位數相除的結果，數字見 §7 表格。差距很依賴題目本身。output tokens 兩組的範圍有大幅重疊，見 §7。這個倍數不能當單一結論引用。而且帶 skill 組的成本，是綁在一起的。受測 skill 跟版面設計 skill，兩個一起跑，沒辦法分開算。

這句話一定要整句連後半段一起講，只講前半就是超賣。還有一件事。句子裡「唯一一處內容層級的捏造」那一格，來自〈跨模型一致性複判〉。它就是那一節提到的第二個灰色地帶。如果把明標為例示的值視為豁免，那一格會翻成通過，兩組差異就只剩日期一項。引用這句話時，這個但書要跟著走。這件事真的發生過。最早的摘要把兩個灰色地帶壓成一句通則，後來才修正。摘要一壓縮就會失真。

### 不能說（逐條，附理由）

1. **「skill 讓事實紀律變差」，或任何因果句。** 差距是同一個習慣重複三次，都是一行帶日期的出處註記，不是三次獨立的紀律失敗。統計上也不可分。Fisher 單尾 p=0.05、雙尾 0.10，算的是 3/3 vs 0/3。這個 p 值假設同一格的三次 run 互相獨立。但 §10 指出，同一格的 run 高度相似。所以它只能當保守參考，不能當統計證據。
2. **「對照組在各項計分斷言上都至少一樣好」。** 這句在題級是錯的。陷阱題的 `fact-no-fabricated-id`，with_skill 是 3/3，對照組是 2/3。
3. **「with_skill 會捏造日期」。** 它加的是真實產出日的出處註記，不是對事件的日期宣稱。
4. **「skill 的驗收關卡沒有價值」。** skill 的 Step 3，是對照材料逐點驗收後才發佈。這一步在這次量測環境裡**根本沒被執行**，單一 executor 一路做完。這次 run 對它零資訊。
5. **任何關於真實使用情境的推論。** 真實使用者的 prompt，不會自帶「只能使用材料裡的資訊」這句話。
6. **兩組品質相等。** 不計分的觀察，記到了真實行為差異，也就是 §8 的靜默略過 vs 主動標示。計分表把它壓平了。
7. **跨模型或跨任務型態的任何宣稱。** executor 全是同一個模型，三題也是同一種任務型態。

### 補記（2026-08-11，維護者指出）：量測環境的注入未隔離

這次的執行環境，載著維護者的整套全域設定。規則、記憶、其他 skill 的注入，兩組都泡在裡面。這格「harness 條件」是髒的——harness 是指執行環境本身的設定層。而且這個條件讀者無法重現。這條變因在原始限制清單裡沒有被記錄。它是量測完成兩週後，由維護者本人補抓的。連「誠實列限制」這件事本身也會漏。獨立視角、加上時間差，都算複核資源，原因就在這裡。v3 的沙箱隔離（暫存沙箱＋`--setting-sources project --strict-mcp-config`）針對的正是這條。

### 最要緊的一條限制：對照組不是「無 skill」組

三道題的 prompt，對兩個配置**一字不差**地寫了「只能使用材料裡的資訊」。那正是受測 skill 產出模板的核心紀律句。而三份材料本身，就是 skill 的 Step 1 產物。再加上 Step 3 沒有被執行。

所以這個 eval 實際測的是兩邊的對比。一邊是紀律句＋Step-1 材料＋SKILL.md 全文＋版面設計 skill。另一邊是紀律句＋Step-1 材料。skill 的邊際貢獻，被這個設計壓到只剩版面殘餘。而唯一的反向差異，也就是出處註記日期，恰好就是版面殘餘。而且 with_skill 組，是兩個 skill 綁在一起跑的。受測 skill 跟版面設計 skill，SKILL.md 明令先載入後者。這個設計，沒辦法分解出差異來自哪一個。

佐證：陷阱題兩組連免責句都幾乎同文。這顯示裁決紀律是**共享材料**驅動，不是 skill 驅動。

這個限制，源自預先登錄的 prompt 寫法本身，不是執行時引入的。v3 若要測 skill 的真實邊際貢獻，有兩件事要改。第一，對照組的 prompt 必須拿掉紀律句。材料也不能由 skill 的 Step 1 產生。第二，對照組必須是「skill 不在可用清單上」，不只是「沒用」。

## 10. 剩下的天花板在哪裡

v2 修掉了 v1 的模板題天花板，但沒修掉全部。96 個計分格裡，只有 4 格非通過，而且集中在兩個單一習慣上。eval 2 兩組 30/30 全過，零鑑別。

最可能的原因是兩條「若引用 X，必須保留脈絡」是條件句。一份完全不提數字的頁面，會自動通過。這次沒有逐份計數，有幾份頁面因為沒引用而空過；§8 只記到一份。多位評分者獨立指出，這獎勵的是「不寫」而非「寫對」。

另外同格內的 run 高度相關。對照組 eval-1 三個 run，時長 68.0／69.6／67.2 秒。output tokens 是 6803／6600／7031，近乎複製品。有效樣本遠小於 n=3 所暗示的。相似度只量了六格中的一格，也就是對照組 eval-1。

> **補正（2026-08-17，事實層；敘事與措辭由維護者另寫）。**
>
> 上一句「近乎複製品」的依據是時長與 output tokens。
>
> 2026-08-13 曾用 difflib 測過三份輸出的文字相似度。得到 23%／39%／37%。當時把這個結果記為「翻案」，也就是推翻了「近乎複製品」這個判斷。
>
> 08-17 逐字重跑同一個腳本，確認那次測量有問題。它只去掉了 `<tag>`，沒有去掉 `<style>` 裡的內文。測到的字串共 6360 字元，其中 5437 字元是 CSS。它還受 `SequenceMatcher` 預設的 autojunk 設定影響。所以 23%／39%／37% 這三個數字作廢。
>
> 08-17 重新測量，做法是先去掉 `<script>`／`<style>` 區塊。再去標籤、壓空白，留下可見文字。這樣約 920–970 字元。用 `SequenceMatcher.ratio()` 計算。並先拿 run-1 跟自己比一次。確認得 1.0，這叫「自證」，用來確認腳本本身沒壞。正式結果如下：run-1／run-2＝87%。run-1／run-3＝82%。run-2／run-3＝84%。autojunk 開或關，結果相同。
>
> 句級對照的結果：章節、六軸表內容、兩條結論，三份一致。差異只在措辭與段落編號，run-2 多一行來源標註。

## 11. v3 候選（來自評分者對判斷標準本身的批評，未裁）

1. **出處註記／頁尾後設資料是否豁免，必須寫死。** 這是這次最高槓桿的灰區。嚴格解讀會讓六份中五份失分，而且跟內容正確性無關。
2. **條件式斷言改成正向要求**（「必須引用且必須保留脈絡」），否則獎勵的是迴避。
3. **動態內容的判斷標準缺口。** 有頁面用 `new Date()`，在互動時寫入當下日期，靜態掃描完全看不到。斷言需要區分「指涉事件的日期」跟「使用者端時鐘」。
4. **全是負向禁令，沒有一條守內容完整性。** 一份把六軸砍到兩軸的頁面，可以全數通過。
5. **敘事性／框架性添加無人管。** 例如替讀者設定使用情境——不改事實，但屬材料外投射。這是這批頁面差異最大的地方，卻沒有任何斷言在測。
6. **自行為材料未定義的術語下定義。** 有頁面兩次定義同一縮寫，還互相矛盾，沒有任何斷言抓得到。
7. **取向差異應該進計分。** 「靜默略過 vs 主動標示查無」，是來源紀律題的核心風險，目前只落在不計分欄。
8. **評測鷹架洩漏進成品。** 「事實包」這個內部詞，出現在全部 18 份頁面的讀者可見文字裡。渲染後實測，每頁出現 1–6 次。成因是題目 prompt 本身就寫了「事實包見⋯」。v3 的 prompt 需要改寫，否則測到的是評測框架，而不是產品行為。

## 12. 這次的評分流程自己有哪些缺陷（記錄下來，供 v3 修）

- **機械證據前處理，只掃靜態 HTML，會漏檢 JS 注入的內容。** 有 run 的時間線由 JS 陣列注入，靜態抽取只抓到四個日期中的一個。已經用渲染後重掃補齊，判定不變。但如果有頁面把捏造內容放進 JS，只靠靜態掃描就會整批漏檢。v3 的機械檢查應該直接對渲染後的 DOM 取文字。
- **成本記帳偶發不含工具輸入**（18 格中 1 格，見 §7）。
- **一份產出一位評分者**，評分者之間的標準漂移，靠事後跨模型一致性複判補（§6）。v3 應該直接把「同一位判完整組」設為預設，或至少雙評加裁決。
