## 1. 實際執行的組態

| 欄位 | 值 |
|---|---|
| 執行模型（executor） | `claude-sonnet-5`（18 run 全數；執行紀錄與 API 紀錄雙重確認） |
| 評分模型（analyzer） | `claude-opus-5`（18 位，每份產出一位，盲評） |

執行檔位選中間帶模型還有一個方法上的理由：v1 的致命傷是天花板（兩臂全過、零鑑別），中間帶模型才留得下鑑別空間。

## 2. 開跑前決定並記錄的兩項處置（不涉判準修改）

**(a) 受測用材料移除設計者引言。** 三份材料開頭的引言區塊寫的是陷阱設計本身（哪一題是乾淨對照、哪個數字查無原句）——交給受測者等於連答案卷一起發下去。處置：只移除引言、標題改中性，正文起逐字保留；兩配置拿到完全相同的材料。

**(b) gate 的「不橫向捲動」以實際渲染量測。** 375×812 視窗、同源 iframe 載入，比對 `documentElement.scrollWidth`／`body.scrollWidth` 與 `clientWidth`。超寬元素若包在自身可捲動容器內、文件本身不捲，不算不過。視窗寬度 375 為本次選定並記錄的操作化，預先登錄未指定。

## 3. Gate（不進分）

18 份全數通過「恰一個自包含 HTML／無外部資源／繁體中文」。

自包含的操作化：外部**資源載入**（script[src]、link[href]、img/iframe/media[src]、@import、css url()、fetch/XHR）才算違規；`<a href>` 超連結不算——材料提供了可引用的來源網址，把它們做成連結是正確行為。

橫向捲動首輪 16/18 通過，2 個不過、記 invalid 並補跑：

| run | 量到的值 | 處置 |
|---|---|---|
| eval-2 with_skill run-3 | clientWidth 375，documentElement.scrollWidth 378 | invalid，補跑後通過 |
| eval-2 對照臂 run-1 | clientWidth 375，body.scrollWidth 392 | invalid，補跑後通過 |

原輸出保留，不計通過也不計失敗。補跑用逐字相同的 prompt 與模型檔位。

## 6. 跨模型一致性複判（盲判，一位判完整組六份）

18 份是 18 位不同評分者各判一份，評分者之間可能標準漂移。故對三個決定性項目各派一位複判者，用**同一把尺**重判整組六份、盲於配置。

| 複判項目 | 結果 |
|---|---|
| eval-1 `fact-no-fabricated-id` | 三個 FAIL＝三份 with_skill；三個 PASS＝三份對照臂。**與原評分完全一致** |
| eval-0 `fact-no-fabricated-id` | 唯一 FAIL＝對照臂 run-2。**與原評分完全一致** |
| eval-2 `fidelity-no-26-percent-as-fact` | 六份全 PASS。**與原評分完全一致** |

複判者主動報出兩個高槓桿的**判準灰區**：

- **出處註記寫出材料檔名**：六份中五份寫了（跨兩配置）。複判者統一裁為「自我指涉來源、不算材料外識別碼」；原評分者對此處理不一致。**但三個 FAIL 都獨立錨在日期上，故此灰區不影響任何判定**。
- **「例示版本號 vs 抽象術語」**：`1.2.3`（具體值）判違規、`sha 形式`／`semver`（術語標籤）不判。若把明標為例示的值視為豁免，eval-0 那格翻成通過、六份全過。

## 9. 這次 run 能說與不能說的話

### 能說（描述性，僅限本次 run）

> 在 16 條計分斷言的總和上，不帶 skill 的對照組不低於帶 skill 組（47/48 vs 45/48）。最大的單項差異出現在乾淨對照題：三份 with_skill 頁面都在出處註記加了材料沒供給的日期，對照臂零份。反向地，唯一一處**內容層級**的捏造出現在對照臂（陷阱題補上例示版本號 `1.2.3`）。帶 skill 組的時長與 output tokens 約為 2.5–3 倍。

這句話必須整句帶著後半段一起講。只講前半＝超賣。另注意：句中「唯一一處內容層級的捏造」那一格即 §6 的第二個灰區——若把明標為例示的值視為豁免，該格翻成通過、兩組差異只剩日期一項。引用本句時此 caveat 要跟著走（實際發生過：首發摘要曾把兩個灰區壓成一個通則，事後修正——摘要層壓縮失真的實例）。

### 不能說（逐條，附理由）

1. **「skill 讓事實紀律變差」或任何因果句。** 差距是同一個習慣重複三次（一行帶日期的出處註記），不是三次獨立的紀律失敗；統計上不可分（3/3 vs 0/3 的 Fisher 單尾 p=0.05、雙尾 0.10）。
2. **「對照臂在各項計分斷言上都至少一樣好」。** 題級是錯的——陷阱題的 `fact-no-fabricated-id` 是 with_skill 3/3、對照臂 2/3。
3. **「with_skill 會捏造日期」。** 它加的是真實產出日的出處註記，不是對事件的日期宣稱。
4. **「skill 的驗收關卡沒有價值」。** skill 的 Step 3（對照材料逐點驗收後才發佈）在本次量測環境裡**根本沒被執行**——單一 executor 一路做完。本次 run 對它零資訊。
5. **任何關於真實使用情境的推論。** 真實使用者的 prompt 不會自帶「只能使用材料裡的資訊」。
6. **兩臂品質相等。** 不計分的觀察記到了真實行為差異（§8 的靜默略過 vs 主動標示），計分表把它壓平了。
7. **跨模型或跨任務型態的任何宣稱。** executor 全是同一模型，三題同一型任務。

### 補記（2026-08-11，維護者指出）：量測環境的注入未隔離

本次執行環境載著維護者的整套全域設定——規則、記憶、其他 skill 的注入，兩臂都泡在裡面。這格「harness 條件」是髒的，而且是讀者無法重現的條件。此變因在原始限制清單裡沒有被記錄，是量測完成兩週後由維護者本人補抓的——連「誠實列限制」這件事本身也會漏，這就是為什麼獨立視角（與時間）都算複核資源。v3 的沙箱隔離（暫存沙箱＋`--setting-sources project --strict-mcp-config`）針對的正是這條。

### 最要緊的一條限制：對照組不是「無 skill」組

三道題的 prompt 對兩個配置**一字不差**地寫了「只能使用材料裡的資訊」——那正是受測 skill 產出模板的核心紀律句。而三份材料本身就是 skill 的 Step 1 產物。再加上 Step 3 未執行。

所以這個 eval 實際量的是：**（紀律句＋Step-1 材料＋SKILL.md 全文＋版面設計 skill）對比（紀律句＋Step-1 材料）**。skill 的邊際貢獻被設計壓到只剩版面殘餘——而唯一的反向差異（出處註記日期）恰好就是版面殘餘；且 with_skill 臂是受測 skill 與版面設計 skill 的捆綁（SKILL.md 明令先載入後者），本設計無法分解差異來自哪一個。

佐證：陷阱題兩臂連免責句都幾乎同文，顯示裁決紀律是**共享材料**驅動，不是 skill 驅動。

這個限制源自預先登錄的 prompt 寫法本身，不是執行時引入的。v3 若要量 skill 的真實邊際貢獻，對照臂的 prompt 必須拿掉紀律句、且材料不能由 skill 的 Step 1 產生——並且對照臂必須是「skill 不在可用清單上」，不只是「沒用」。

## 10. 天花板仍在，只是位置換了

v2 修掉了 v1 的模板題天花板，但沒修掉全部：96 個計分格裡只有 4 格非通過，且集中在兩個單一習慣上。eval 2 兩臂 30/30 全過、零鑑別。

主因是兩條「若引用 X，必須保留脈絡」是條件句——**一份完全不提數字的頁面自動通過**。多位評分者獨立指出這獎勵的是「不寫」而非「寫對」。

另外同格內的 run 高度相關：對照臂 eval-1 三 run 時長 68.0／69.6／67.2 秒、output tokens 6803／6600／7031——近乎複製品。有效樣本遠小於 n=3 所暗示的。

> **補正（2026-08-17，事實層；敘事與措辭由維護者另寫）**：上句「近乎複製品」的依據是時長與 output tokens。2026-08-13 曾以 difflib 量三份輸出的文字相似度得 23%／39%／37%（當時記為翻案）——08-17 逐字重跑該腳本確認：它只去掉 `<tag>`、未去掉 `<style>` 內文，量到的字串 6360 字元中 5437 字元是 CSS，並受 `SequenceMatcher` 預設 autojunk 影響；該三個數字作廢。08-17 重測（去 `<script>`／`<style>` 區塊＋去標籤＋壓空白後的可見文字，約 920–970 字元；`SequenceMatcher.ratio()`，run-1 自比＝1.0 自證）：run-1／run-2＝87%、run-1／run-3＝82%、run-2／run-3＝84%（autojunk 開或關結果相同）。句級對照：章節、六軸表內容、兩條結論三份一致；差異在措辭與段落編號，run-2 多一行來源標註。


## 11. v3 候選（來自評分者對判準本身的批評，未裁）

1. **出處註記／頁尾後設資料是否豁免，必須寫死。** 本次最高槓桿的灰區——嚴格解讀會讓六份中五份失分，且與內容正確性無關。
2. **條件式斷言改成正向要求**（「必須引用且必須保留脈絡」），否則獎勵迴避。
3. **動態內容的判準缺口。** 有頁面用 `new Date()` 在互動時寫入當下日期，靜態掃描完全看不到。斷言需區分「指涉事件的日期」與「使用者端時鐘」。
4. **全是負向禁令，沒有一條守內容完整性。** 一份把六軸砍到兩軸的頁面可以全數通過。
5. **敘事性／框架性添加無人管。** 例如替讀者設定使用情境——不改事實但屬材料外投射，是這批頁面差異最大的地方，卻沒有任何斷言在量。
6. **自行為材料未定義的術語下定義。** 有頁面兩次定義同一縮寫且互相矛盾，沒有任何斷言抓得到。
7. **取向差異應該進計分。** 「靜默略過 vs 主動標示查無」是來源紀律題的核心風險，目前只落在不計分欄。
8. **評測鷹架洩漏進成品。**「事實包」這個內部詞出現在全部 18 份頁面的讀者可見文字裡（渲染後實測，每頁 1–6 次）。成因是題目 prompt 本身就寫了「事實包見⋯」——v3 的 prompt 需改寫，否則量到的是評測框架而非產品行為。

## 12. 本次評分管線自身的缺陷（記錄，供 v3 修）

- **機械證據前處理只掃靜態 HTML，會漏檢 JS 注入的內容。** 有 run 的時間線由 JS 陣列注入，靜態抽取只抓到四個日期中的一個。已用渲染後重掃補齊、判定不變；但若有頁面把捏造內容放進 JS，只靠靜態層就會整批漏檢。v3 的機械層應直接對渲染後的 DOM 取文字。
- **成本記帳偶發不含工具輸入**（18 格中 1 格，見 §7）。
- **一份產出一位評分者**，評分者之間的標準漂移靠事後跨模型一致性複判補（§6）。v3 應直接把「同一位判完整組」設為預設，或至少雙評＋裁決。
